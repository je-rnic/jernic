<Statement label="The challenge" tone="dark">
  How could we make AI news analysis <strong>easy to understand</strong> and <strong>natural to use</strong> where people already read?
</Statement>

<section className="editorial-section editorial-section--solutions" aria-labelledby="checkmate-system-title">
  <div className="editorial-section__intro flow">
    <p className="editorial-eyebrow">03. Shaping the experience</p>
    <h2 id="checkmate-system-title" className="type-title">A reading journey across three channels</h2>
    <p>I used the research to frame two design priorities: an accessible starting point and a manageable analysis view. I documented the flows and reusable components in Figma and Confluence, then carried those decisions into React.</p>
  </div>
  <div className="solution-list">
    <article className="solution">
      <div className="solution__copy flow">
        <p className="editorial-eyebrow">Entry points</p>
        <h3 className="type-title">Start close to the article</h3>
        <p>The Chrome extension and Telegram bot gave readers ways to submit an article within their existing browsing and messaging habits. The website provided space for the detailed analysis.</p>
        <p>The bot returned a summary with a link to the full analysis. That made access to the link a critical part of the journey, particularly when a response became long.</p>
      </div>
      <Figure
        caption="Asset to add: a journey diagram using the existing screens. Show Telegram article submission → bot summary → detailed website analysis, with the Chrome extension as a second entry point into article analysis."
        aspect="16/9"

    </article>
    <article className="solution solution--reverse">
      <div className="solution__copy flow">
        <p className="editorial-eyebrow">Information hierarchy</p>
        <h3 className="type-title">Give each analysis room to be read</h3>
        <p>The output covered four categories: fact-checking, emotion, sentiment and propaganda techniques. I organised them into selectable tabs so readers could focus on one category at a time.</p>
        <p>The trade-off was that comparing categories required switching views. Prototype testing therefore needed to examine how people found a result and moved between tabs.</p>
      </div>
      <Figure
        src="/images/work/checkmate/designsystem-structure.jpg"
        alt="CheckMate analysis components organised into separate categories and selectable tabs."

        <h3 className="type-title">Carry the hierarchy into the interface</h3>
        <p>I defined reusable typography, colour and component treatments to keep the analysis views consistent. Inter separated headings, labels and body copy through weight; primary blue identified actions and selected states.</p>
        <p>Building the React interface alongside the Figma reference let me carry that hierarchy into component states and navigation behaviour.</p>

<section className="editorial-section editorial-section--process" aria-labelledby="checkmate-performance-title">
  <div className="editorial-section__intro flow">
    <p className="editorial-eyebrow">06. Implementing the experience</p>
    <h2 id="checkmate-performance-title" className="type-title">Designing for the time between actions</h2>
    <p>Moving from the mockup into implementation exposed a constraint that a static prototype could not fully represent: machine-learning analysis could take time, particularly for longer articles.</p>
    <p>Together with the team, I worked on <strong>route-based lazy loading</strong> and <strong>client-side API response caching</strong>. These choices addressed page loading and revisiting results; model inference time remained a separate constraint.</p>
    <p>A measured before-and-after performance comparison is not available for this case study, so these implementation choices are described without a quantified speed improvement.</p>
    <div className="stats">
      <p className="type-eyebrow">| design lesson</p>
      <p className="type-serif">Loading behaviour and repeated waits are part of the reading experience too.</p>
    </div>
  </div>

  <div className="editorial-section__intro flow">
    <p className="editorial-eyebrow">08. Takeaways</p>
    <h2 id="checkmate-reflection-title" className="type-title">The design system continues in the code</h2>
    <p>Owning both the design reference and the React interface made consistency tangible. Component states, navigation, responsive layouts and loading behaviour all affected how the intended experience survived implementation.</p>
    <p>The Telegram issue reinforced the need to follow a journey beyond an individual screen: a readable summary still depended on an accessible link to the next step. Evaluating the revised mockup and then testing the implemented flow with the client addressed different stages of that journey.</p>
  </div>
  <div className="editorial-section__intro flow">
    <h3 className="type-title">What I would validate next</h3>
    <p>I would test whether readers correctly understand uncertain model outputs, distinguish sentiment from factual accuracy and explain why a claim was flagged. That would connect the goal of approachable analysis with evidence of comprehension and better-informed judgement.</p>
    <p>I would also evaluate the waiting experience on slower connections and measure initial-load and repeat-visit performance to establish the user benefit of the implementation choices.</p>
    <blockquote className="editorial-quote">
      <p><em>A consistent interface starts in Figma, but its behaviour is decided just as much in the browser.</em></p>
