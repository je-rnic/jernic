  <div className="editorial-section__intro flow">
    <p className="editorial-eyebrow">08. Takeaways</p>
    <h2 id="checkmate-reflection-title" className="type-title">The design system continues in the code.</h2>
    <p>CheckMate let me take responsibility for both the design reference and the interface people used. That made consistency tangible: component states, navigation, responsive layouts and loading behaviour all affected whether the intended experience survived implementation.</p>
    <p>My strongest takeaway was to treat frontend decisions as design decisions. A reusable component can preserve an interaction pattern; caching can reduce a repeated wait; a clear analysis structure can make complex output easier to approach.</p>
  </div>
  <div className="editorial-section__intro flow">
    <h3 className="type-title">What I would validate next.</h3>
    <p>I would test whether readers correctly understand uncertain model outputs and can explain why a claim was flagged. Task completion tells me that someone can reach a result; comprehension testing would help establish whether that result supports better judgement.</p>
    <p>I would also evaluate the waiting experience on slower connections and measure initial-load and repeat-visit performance. That would connect the implementation choices to observed user benefit.</p>
    <blockquote className="editorial-quote">
      <p><em>A consistent interface starts in Figma, but its behaviour is decided just as much in the browser.</em></p>
    </blockquote>
